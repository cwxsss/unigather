# UniGather 仪表盘、任务完成进度与附件分类归档设计

## 目标

重新划分仪表盘与收集任务页面的职责，并让任务进度准确表达整个材料收集工作的完成程度。完善附件打开体验，将匹配和未匹配材料分类归档，并按任务配置的统一名称重命名匹配材料。

## 模块边界

### 仪表盘

仪表盘只展示系统级运行概况，不再展示某一个收集任务的单位反馈进度。

仪表盘包含：

- 收集任务总数、进行中数量和最近一次收件状态。
- 邮件发送批次数、今日正式发送成功数和失败数。
- “材料收集”和“邮件发送”两个核心工作台入口。
- 最近系统动态，包括任务收件完成、发送批次完成和失败待重试等事件。

仪表盘不再包含：

- 单个任务进度条。
- 单位反馈状态图。
- 单个任务的已反馈、待反馈、待确认和未匹配统计。

### 收集任务

收集任务页面承接所有收件业务统计：

- 任务总数。
- 进行中任务数。
- 当前筛选任务的已完成反馈单位数。
- 当前筛选任务的待反馈单位数。
- 每个任务的整体完成进度。
- 当前任务的已反馈、待反馈、待确认、未匹配状态分布。
- 当前任务匹配到的邮件、附件和匹配原因。

页面默认展示全部任务；反馈状态区域通过任务选择器切换具体任务，不把多个任务的单位状态简单相加。

## 任务完成进度口径

任务完成进度固定为：

```text
已确认完成反馈的单位数量 / 本任务应反馈单位总数
```

规则：

- 单位存在至少一封状态为 `confirmed` 的有效匹配邮件时，该单位记为已完成。
- 同一单位发送多封邮件或多个附件，只计算为一个已完成单位。
- `needs_review`、`unmatched` 和 `ignored` 邮件不计入已完成数量。
- 人工确认邮件归属后，相应单位立即转为已完成并重新计算任务进度。
- 删除、忽略或人工改派匹配结果后，系统根据该单位是否仍存在其他有效确认邮件重新计算状态，避免进度只增不减。
- 完成进度与“本次同步命中邮件数”彻底解耦；同步命中数量只显示在同步记录中。
- 当所有任务范围内单位都完成反馈时，任务进度显示 100%；任务状态是否自动切换为 `completed` 保持现有规则，本次不新增自动结束行为。

## 附件归档结构

每个收集任务建立独立目录，并在任务目录下创建两个状态目录：

```text
材料保存根目录
└─ 任务名称
   ├─ 已匹配
   └─ 未匹配
```

任务名称和文件名中的 Windows 非法字符统一替换为安全字符。目录不存在时在第一次归档时自动创建。

### 已匹配附件

新建和编辑任务增加“材料统一名称”字段：

- 默认值为任务名称。
- 用户可以为每个任务单独修改。
- 编辑任务时完整回显。
- 旧任务没有该字段时，以任务名称作为兼容默认值。

匹配成功后的文件名格式为：

```text
单位名称-材料统一名称.原扩展名
```

示例：

```text
重庆-2026年数据安全报名表.docx
```

重名规则：

- 保留原附件扩展名。
- 同一单位、同一统一名称和同一扩展名出现多份附件时，追加 `-2`、`-3` 等序号。
- 任何情况下都不得覆盖现有文件。

### 未匹配附件

未匹配附件保存到任务的“未匹配”目录，命名格式为：

```text
接收时间-发件邮箱-原文件名
```

规则：

- 接收时间使用 `yyyyMMdd-HHmmss`。
- 发件邮箱和原文件名进行 Windows 文件名安全处理。
- `needs_review` 和 `unmatched` 的附件均进入“未匹配”目录。
- 邮件没有附件时只保存匹配记录，不创建空文件。

### 人工确认后的移动

待确认或未匹配邮件经人工确认到具体任务和单位后：

- 将已归档附件从“未匹配”移动到相应任务的“已匹配”目录。
- 按“单位名称-材料统一名称”重新命名。
- 数据库中的 `saved_path` 同步更新。
- 目标目录存在同名文件时追加序号。
- 移动失败时保留原文件和原数据库路径，显示明确错误，不产生只有数据库更新而文件未移动的状态。

## 文件打开交互

收件箱附件和任务详情附件均提供两个明确操作：

- “打开文件”：使用 Windows 默认程序打开附件。
- “打开所在目录”：调用资源管理器并选中该附件；如果选中能力不可用，则打开附件所在目录。

规则：

- 附件没有本地保存路径时，按钮显示不可用，并提示“附件尚未归档到本地”。
- 文件已被移动或删除时，显示实际路径和错误信息。
- 目录打开接口只接受数据库中已经归档的文件路径，不接受网页传入的任意未验证路径。

## 数据模型与接口

### 数据模型

扩展 `tasks`：

- `material_name TEXT NOT NULL DEFAULT ''`：任务级材料统一名称；空值读取时回退到任务名称。

继续使用：

- `task_companies.feedback_status` 表示单位反馈状态。
- `matches.status` 和 `matches.company_id` 表示邮件匹配结果。
- `attachments.saved_path` 表示附件当前本地路径。

### 后端接口

- 扩展 `task_create` 和 `task_update`，保存 `material_name`。
- 扩展 `task_list`，返回 `material_name` 和按有效匹配结果重新计算的单位完成统计。
- 扩展 `task_match_detail`，返回附件名称、本地路径和打开能力状态。
- 新增 `dashboard_summary`，返回收件任务、发送批次、今日收发和最近系统动态的聚合结果。
- 新增 `material_open_location(path)`，打开资源管理器并定位文件。
- 归档逻辑根据匹配状态选择任务的“已匹配”或“未匹配”目录。
- `match_resolve` 完成人工确认、文件移动、路径更新和单位反馈状态重算。

## 数据流

### 自动收件

1. 按任务时间范围收取邮件。
2. 保存邮件和匹配结果。
3. 对每个附件判断匹配状态。
4. 已确认匹配的附件进入“已匹配”目录并统一命名。
5. 待确认和未匹配附件进入“未匹配”目录并保留来源信息。
6. 根据每个单位是否存在有效确认匹配重新计算单位反馈状态。
7. 前端刷新任务完成进度、反馈状态和匹配邮件列表。

### 人工确认

1. 用户选择任务和单位并确认邮件归属。
2. 后端先计算目标文件路径和冲突序号。
3. 移动附件成功后，事务更新匹配记录、附件路径和单位反馈状态。
4. 任一文件移动失败则不提交数据库状态变更，并显示可操作的错误信息。

## UI 设计

### 仪表盘

采用已确认的双工作台科技感布局：

- 顶部四个紧凑指标卡展示收件任务、发送批次、今日收取邮件和今日成功发送。
- 中部展示“材料收集”和“邮件发送”两个工作台状态卡。
- 底部展示最近系统动态。
- 所有卡片可跳转到相应业务页面或历史详情。

### 收集任务

- 顶部增加任务总数、进行中、已完成反馈单位、待反馈/待确认四个统计卡。
- 任务列表每行展示任务名称、单位完成数量、最近收件时间和整体完成百分比。
- 反馈状态区域位于任务列表下方，通过任务下拉框选择具体任务。
- 任务详情继续展示匹配邮件列表，并为附件增加“打开文件”和“打开所在目录”。
- 新建/编辑任务表单在基础信息区域增加“材料统一名称”，提示最终命名示例。

## 错误处理

- 根目录无写入权限时，本次附件标记归档失败，并显示具体目录和系统错误。
- 已匹配目录创建失败时不回退写入未匹配目录，避免状态和目录不一致。
- 文件移动跨磁盘失败时使用“复制成功后删除源文件”的兼容方式；删除失败则保留源文件并记录重复文件警告。
- 数据库更新失败时，不删除已存在的原文件；需要执行补偿移动或保留可追溯错误记录。
- 仪表盘聚合接口失败时，各区域显示独立错误，不影响用户进入收集任务或邮件发送页面。

## 兼容性

- 旧任务自动以任务名称作为材料统一名称。
- 旧附件路径继续可打开，不强制批量迁移已有文件。
- 新分类归档规则只作用于新同步和人工重新确认的附件。
- 不删除历史任务、历史邮件、历史附件或历史发送批次。
- 数据库仍固定在可执行文件所在目录。

## 测试与验收

- 验证任务进度按单位完成数量计算，同单位多封邮件不会重复增加进度。
- 验证取消、忽略和改派唯一确认邮件后，单位状态和任务进度能够回退。
- 验证仪表盘同时显示收件与发件统计，且不再出现单任务反馈图。
- 验证收集任务页面完整显示任务统计、任务进度和具体任务反馈状态。
- 验证旧任务的统一名称回退到任务名称。
- 验证匹配、待确认和未匹配附件进入正确目录。
- 验证统一命名、扩展名保留、非法字符处理和重名序号。
- 验证人工确认后文件移动、重命名和数据库路径同步。
- 验证“打开文件”和“打开所在目录”的成功、无路径和文件丢失场景。
- 运行 `npm test`、`cargo test --manifest-path src-tauri/Cargo.toml`、`npm run build` 和 `npm run tauri -- build`。
- 仅生成本地安装包，不推送 GitHub、不发布 Release。

## 不在本次范围

- 不自动催办未反馈单位。
- 不把已有历史附件批量搬迁到新目录。
- 不改变邮件发送工作台的点对点发送规则。
- 不根据附件数量计算任务完成进度。
