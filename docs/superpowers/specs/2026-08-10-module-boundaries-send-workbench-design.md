# UniGather 模块边界与独立邮件发送工作台设计

## 目标

将 UniGather 拆分为“收集任务”和“邮件发送”两个完全独立的工作台。收集任务只负责收件匹配和未反馈统计；邮件发送负责扫描材料、匹配通讯录并在人工确认后逐单位发信。两者共享通讯录、邮箱/代理配置、AI 配置和本地文件能力。

## 模块边界

- 收集任务：起止时间、单位范围、主题/正文规则、轮询间隔、AI 匹配、反馈状态。
- 邮件发送：材料目录扫描、匹配预览、邮件内容、批次级抄送、测试发送、正式发送、历史和失败重试。
- 邮件发送不再关联收集任务，不读取任务单位范围或任务附件。

## 配置与数据

- 邮箱配置分为收件连接和发信连接；SMTP 账号默认复用收件账号，代理和 Windows 凭据复用现有配置。
- 通讯录保留现有单位、联系人和邮箱，扩展电话与单位别名；旧版导入模板继续兼容。
- 新增独立发送批次与批次明细，保存扫描目录、匹配方法、置信度、人工决策、发送状态和错误；旧发送记录不删除。

## 匹配与发送安全

1. 人工规则和单位别名优先。
2. 标准化文件名精确匹配。
3. 本地模糊匹配。
4. AI 仅处理低置信度项目，且不上传附件内容。

一份附件多候选、未匹配、无邮箱和重复使用默认阻止正式发送。同一单位多份附件合并成一封邮件，同单位邮箱合并到 To，批次级抄送放入 CC。必须测试发送成功并输入“确认发送”后才能正式发送。

## 界面

- 收集任务窗口使用 960px 左右宽度、双栏紧凑布局、单位列表独立滚动、固定底部操作栏；小屏自动单栏。
- 邮箱配置显示收件/发信两个连接卡片。
- 邮件发送使用“材料来源 → 自动匹配 → 邮件内容 → 检查与发送”四段式工作台。

## 验收

- 1280×720 下任务窗口字段、单位列表和操作栏完整可用。
- 旧/新通讯录模板、SMTP/代理、目录扫描、匹配、AI 数据边界、逐单位发送、失败重试和安装包构建均通过测试。
