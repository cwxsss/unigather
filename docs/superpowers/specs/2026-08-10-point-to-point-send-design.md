# UniGather 点对点发送设计

## 目标

将 Mass-email v0.1.1 的核心发送能力整合到 UniGather：使用 SMTP/TLS 和现有 HTTP/SOCKS5 代理，按单位逐封发送，避免不同单位之间相互暴露收件地址；可复用当前邮箱账号在 Windows 凭据管理器中的密码，并将发送结果留在本机。

## 交互

新增“邮件发送”模块。用户选择一个收集任务和本次要发送的单位，填写 SMTP 服务器、端口、加密方式、发件人名称、主题和正文。单位列表按行显示联系人邮箱；每个单位单独生成一封邮件，主送只包含该单位的邮箱，抄送不跨单位复用。可选附加该任务已经确认归属的本地材料附件。

发送前执行检查：SMTP 配置、邮箱账号、单位邮箱、正文和附件路径必须有效；重复主送邮箱、缺少附件和未确认匹配显示为风险或阻断项。用户先向内部测试邮箱发送一封测试邮件，确认测试成功后才能正式发送；正式发送还要求输入“确认发送”。

## 本地后端

- `send_test`：使用第一个选中单位生成一封测试邮件，收件人替换为内部测试邮箱。
- `send_start`：启动后台发送任务，按单位逐封发送并实时更新进度。
- `send_status`：查询发送进度。
- `send_runs`、`send_items`：SQLite 保存批次、单位、状态、错误类型、发送时间，不保存密码。
- SMTP 客户端原生使用当前 Rust 服务，通过现有代理连接器建立 TCP，支持 SSL/TLS、STARTTLS、HTTP CONNECT 和 SOCKS5。
- 邮箱密码、代理密码只从 Windows 凭据管理器读取；发送日志和 SQLite 不包含密码或完整 MIME 内容。

## 验证

纯函数测试覆盖邮箱/单位校验、测试发送状态、重复收件人风险、MIME 头编码和附件目录越界；Rust 测试覆盖 SMTP 命令解析和 MIME 构造。集成构建验证 Tauri 命令注册、前端构建和 Windows 安装包。
