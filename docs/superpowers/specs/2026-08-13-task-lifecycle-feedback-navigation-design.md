# UniGather 任务生命周期、反馈分页与导航体验设计

## 1. 产品摘要

### 用户、问题与价值

UniGather 面向总部单人材料收集人员。当前任务删除会直接触发数据库外键问题，已中断任务不具备明确的可恢复入口；反馈邮件使用内部滚动容器，长列表难以定位；侧栏会随主内容移动；收件箱时间输入不够直观。

本次设计将任务删除改为可恢复的软删除，并将任务状态入口、反馈分页、固定导航和收件时间选择统一为可预期、可回退的桌面交互。

### 范围

- 收集任务的软删除、已删除任务查看与恢复。
- 反馈状态与匹配邮件的表格分页。
- 桌面端固定侧栏及导航顺序调整。
- 收件箱“收件起始时间”的可选、可输入时间控件，移除冗余刷新按钮。

不包含邮件匹配算法、历史邮件/附件删除、GitHub 发布或版本号变更。

### 约束与成功信号

- 平台维持 Tauri 2 + 原生 HTML/CSS/JavaScript + Rust/SQLite，本地单用户、Windows 桌面应用。
- 维持既有深色科技感视觉语言与 980px 最小窗口宽度。
- 任务、邮件与附件数据不得因“删除任务”丢失。
- 成功信号：用户可在不滚动侧栏的情况下切换页面；可确认删除、查看并恢复任务；反馈邮件按页浏览；可通过日历或键盘输入收件起始时间。

## 2. 信息架构与主流程

### 左侧导航顺序

1. 仪表盘
2. 通讯录
3. 收件箱
4. 收集任务
5. 邮件发送
6. 邮箱配置
7. 材料归档
8. 系统设置

侧栏固定在应用窗口左侧，主内容区域单独滚动。窗口小于既有最小宽度时仍维持桌面布局，不引入移动端抽屉导航。

### 任务删除与恢复流程

1. 用户在任务卡片或任务管理中点击“删除”。
2. 系统弹出确认对话框，明确说明任务会移入“已删除”，邮件、附件、匹配记录与发送记录不会被清除。
3. 用户确认后，任务停止自动收件，进入已删除状态，并从正常任务列表移除。
4. 用户点击收集任务顶部“已删除”统计卡，在任务管理中查看已删除任务。
5. 用户点击“恢复”，任务恢复为**已中断**状态，不自动恢复轮询；用户可编辑后选择“立即运行”。

恢复为已中断是安全默认值，避免误恢复后对历史时间范围自动重复收件。已删除任务保存 30 天；到期后仅提示可由用户手动彻底清理的候选项，本次不实施自动物理删除。

### 反馈邮件浏览流程

1. 用户选择任务，在“反馈情况”选择筛选项：全部、已匹配、待确认、未匹配。
2. 系统按筛选结果分页加载，默认每页 20 条，可选 10、20、31、40、50 条。
3. 用户使用“上一页/下一页”或页码跳转，不使用表格内部滚轮承载完整数据。
4. 点击某行“查看邮件”，切换到收件箱并打开对应邮件详情。

### 收件箱收件流程

1. 用户通过本机日期/时间选择器选择起始时间，或直接键入日期和时间。
2. 未填写时保留既有默认：收取近 7 天邮件。
3. 点击“立即收件”，使用该起始时间执行收件并显示进度。
4. 删除“刷新”按钮；邮件列表数据在收件完成、切换至收件箱及执行筛选时加载。

## 3. 页面规格

### 收集任务页

**目的**：管理任务状态和查看任务反馈。

顶部统计卡为“任务总数、进行中、已完成、已删除”。点击任一卡片打开任务管理弹窗并默认应用相应筛选。已删除统计卡的说明文案为“查看可恢复任务”。

正在进行的任务仍只展示可自动收件的任务。已删除任务不出现在此列表、仪表盘进度、定时轮询和待反馈导出中。

反馈区域采用固定高度的普通表格区；数据区仅显示当前页，分页器位于表格底部，包含“第 X / Y 页，共 N 封”“上一页”“下一页”和页码选择。表头固定在本页容器顶部；页面整体滚动由主内容区承载。

### 任务管理弹窗

筛选项调整为“全部任务、进行中、已完成、已删除”。已删除行显示删除时间和“恢复”按钮，不显示“立即运行、标记完成”等运行态操作。正常任务行保留查看详情、编辑、重命名、停止、立即运行、删除等与其状态相符的操作。

删除按钮必须打开确认弹窗，不能直接调用删除命令。确认弹窗按钮顺序为“取消 / 确认删除”；确认删除为红色危险操作，焦点默认落在“取消”。按 Esc 或点击遮罩关闭且不删除。

### 收件箱

顶部操作区仅保留“收件起始时间”和“立即收件”。时间控件使用 `datetime-local`，保留键盘输入、复制粘贴及本机日期/时间面板选择能力；显示辅助说明“留空时默认收取近 7 天”。

移除“刷新”按钮及对应提示；筛选、排序不触发服务器收件，仅处理本地已同步邮件。

## 4. 组件契约

| 组件 | 输入 | 事件/输出 | 状态 |
| --- | --- | --- | --- |
| 任务状态统计卡 | `count`、筛选值 | `openTaskManagement(filter)` | 正常、0 条 |
| 删除确认对话框 | `taskId`、任务名称 | `confirmDelete`、`cancel` | 打开、删除中、失败 |
| 已删除任务行 | 任务、删除时间 | `restoreTask(taskId)` | 可恢复、恢复中、恢复失败 |
| 反馈分页器 | `page`、`pageCount`、`pageSize`、`total` | `changePage`、`changePageSize` | 首页、末页、空结果、加载中 |
| 反馈邮件行 | 邮件摘要、匹配状态 | `openFeedbackMessageInInbox(mailId)` | 已匹配、待确认、未匹配 |
| 收件起始时间 | 字符串或空 | `syncInbox(since)` | 默认近 7 天、合法、非法、收件中 |

## 5. 状态矩阵

| 场景 | 页面反馈 | 可用操作与恢复 |
| --- | --- | --- |
| 删除确认 | 显示任务名称、影响说明 | 取消或确认删除 |
| 删除成功 | Toast“任务已移入已删除，可在任务管理中恢复” | 跳转不强制，统计即时刷新 |
| 删除失败 | Toast 显示后端原因，任务保持原状 | 可重试 |
| 已删除为空 | 任务管理显示“暂无已删除任务” | 返回全部任务 |
| 恢复成功 | Toast“任务已恢复为已中断，请按需立即运行” | 可编辑或立即运行 |
| 反馈加载中 | 表格显示骨架行，不改变现有筛选 | 禁用分页按钮 |
| 反馈空结果 | 显示“当前筛选下暂无邮件” | 修改筛选或页大小 |
| 页码越界 | 后端回传最后有效页 | 前端同步页码并重新渲染 |
| 非法时间 | 输入框下显示“请输入有效的日期和时间” | 阻止立即收件 |
| 收件中 | 显示进度条和已处理数量 | 禁用立即收件及时间输入 |

## 6. 交互规则

- 软删除数据模型：任务新增 `deleted_at`、`deleted_previous_status`；正常查询排除 `deleted_at IS NOT NULL`，已删除筛选仅查询该集合。保留原任务 ID，不删除 `matches`、`sync_runs`、`task_companies`、邮件或归档文件。
- 删除任务前，若其状态为 `active`，先停止其轮询资格，再在同一数据库事务写入删除时间和原状态。
- 恢复时清除 `deleted_at`，任务状态固定为 `paused`，清空下次自动收件时间；不重新归档或重新匹配历史邮件。
- 自动完成逻辑、定时轮询、仪表盘统计、待反馈导出都必须过滤已删除任务。
- 分页由后端接受 `task_id`、`filter`、`page`、`page_size`，返回当前页记录、总数、总页数及各状态计数。前端不一次性加载全部匹配邮件。
- 切换筛选或每页数量时重置为第 1 页；跳转收件箱详情时保存当前任务筛选上下文，返回任务页后保留当前页。
- 侧栏 CSS 使用固定或粘性定位，占满视口高度；`main` 为独立 `overflow-y:auto` 滚动容器。模态弹窗打开时继续锁定背景主内容滚动。

## 7. 验收标准

1. **软删除**：给定进行中任务，点击删除并确认后，该任务不再参与自动收件、不出现在进行中列表，且已删除统计增加 1。
2. **恢复**：给定已删除任务，点击恢复后，任务回到已中断状态；原单位、规则、邮件与附件记录仍可读取，且不会自动收件。
3. **取消删除**：给定删除确认框，点击取消或按 Esc 后，数据库和页面任务状态均不变。
4. **删除保护**：已删除任务不能被立即运行、编辑或标记完成；恢复后才显示这些操作。
5. **分页**：给定 51 封匹配邮件和每页 20 条，页面显示 3 页；切换第 2 页只显示第 21–40 条，上一页/下一页边界正确禁用。
6. **筛选分页**：切换状态筛选或页大小后回到第 1 页，总数和页数正确更新。
7. **查看邮件**：点击任一反馈行“查看邮件”后，进入收件箱且对应邮件详情已打开。
8. **固定导航**：主内容滚动至长页面底部时，左侧菜单位置不变，菜单顺序符合本规格。
9. **收件时间**：用户可通过日期面板选择或键盘输入有效时间；空值默认近 7 天；非法输入不会发起收件。
10. **刷新移除**：收件箱顶部不再出现刷新按钮，也不存在无效的刷新点击处理器。

## 8. 实施顺序

1. 数据库迁移与 Rust 任务查询：增加软删除字段、删除/恢复命令、正常查询过滤、分页接口。
2. 为软删除、恢复、分页边界、已删除任务不参与轮询补充 Rust 与 Node 测试。
3. 更新任务状态卡、任务管理、删除确认与恢复交互。
4. 更新反馈表格数据源和分页器，移除内部整表滚动。
5. 调整应用壳层滚动和导航顺序；更新收件箱时间控件与收件按钮区。
6. 执行 `npm test`、`cargo test --manifest-path src-tauri/Cargo.toml`、`npm run build`、`npm run tauri -- build`，仅生成本地安装包。
